# Test Plan — COMFY Website

## 1. Project Overview

**Project Name:** COMFY Website  
**Website:** [https://comfy.ua/](https://comfy.ua/)  
**Testing Type:** Manual Testing  
**Project Type:** E-commerce Website

The purpose of this project is to perform manual testing of the COMFY e-commerce website to evaluate its functionality, usability, user interface, and responsiveness across different screen sizes.

The testing will cover the main website components, including the header, homepage, registration and authorization forms, product catalog, product pages, shopping cart, checkout process, and footer.

## 2. Testing Objectives

- Verify the main website functionality and navigation.
- Check header elements, including the logo, city selection, navigation links, and interactive buttons.
- Verify registration and authorization functionality, including form validation.
- Check product search, filters, and sorting.
- Verify product pages and product information.
- Test adding and removing products from the shopping cart.
- Check the checkout process and form validation.
- Verify promotional banners, product sections, and carousels.
- Test footer navigation links, contact information, and social media links.
- Evaluate UI consistency, usability, and content alignment.
- Verify responsive behavior on desktop, tablet, and mobile devices.
- Identify, document, and report defects.

## 3. Scope of Testing

### In Scope

- Header and main navigation
- Homepage
- Registration functionality
- Authorization and logout functionality
- Product catalog
- Product search
- Product filters and sorting
- Product cards
- Product details page
- Shopping cart
- Checkout process
- Forms and input validation
- Promotional banners and product carousels
- Footer and footer navigation links
- Contact information and social media links
- UI and usability testing
- Responsive layout (Desktop, Tablet, and Mobile)
- API requests related to tested functionality, where accessible

### Out of Scope

- Real purchases and payments
- Testing internal administrative functionality
- Load and performance testing
- Security penetration testing
- Automated testing
- Testing third-party services beyond verifying that the relevant links open correctly

## 7. Entry Criteria

- The website is accessible.
- The main website pages are available.
- The testing environment is prepared.
- The test checklist and test cases are documented.
- Required test data is available, where applicable.
- No critical external issue prevents testing from starting.

## 8. Exit Criteria

- All planned and executable test cases have been executed.
- Test results have been documented.
- Failed and blocked tests have been identified and explained.
- Identified defects have been documented in GitHub with supporting evidence.
- Test execution results have been reviewed.
- A Test Summary Report has been prepared.

## 9. Risks and Limitations

- Website content and functionality may change during testing.
- Some features may require user authentication.
- Registration or authorization may require a real phone number and SMS verification.
- Verification codes may not be available for testing.
- Some functionality may depend on third-party services.
- Real orders and payments will not be completed.
- Some API endpoints may not be publicly accessible.
- Some test scenarios may be blocked by unavailable test data or website restrictions.

## 10. Test Status

**Status:** In Progress

Testing is performed progressively according to the Test Checklist. Test results and identified defects are updated in GitHub throughout the testing process.
